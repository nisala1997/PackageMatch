# PackageMatch

A postpaid package and add-on catalogue with rule-based matching and nearest-option fallback.

## Run locally

Use Node.js 22.13+ and pnpm 11.25.0. In the project folder:

    pnpm install --frozen-lockfile
    pnpm build

On a fresh database, run this once:

    node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_nappy_miek.sql

Start development:

    node scripts/run-framework.mjs dev

Open http://localhost:5173/ directly. Customers do not sign in or enter a phone number.

## Admin login

Create the admin username and password in your local terminal:

    node scripts/setup-staff.mjs

Use at least 9 characters for the password. The script stores a password hash and random signing secret in ignored .dev.vars, without saving the plain password. Restart the server after setup. Open http://localhost:5173/staff/login and sign in to enable Package admin and Sign out. There is no customer login link in the navigation.

The current configuration supports one shared admin account. Sessions last eight hours. Login attempts are limited to 10 per 15 minutes. Running setup again rotates the signing secret and invalidates previous sessions. Phone numbers, old mobile-verification cookies, and ChatGPT mock identities no longer grant admin access. Legacy /verify links redirect to the public portal; mobile verification endpoints are disabled. Package create/update/delete APIs still require an admin session and same-origin requests.

## Normal package catalogue

The supplied 69 entries are normal catalogue records: 15 Data+Voice packages, 18 Data Only packages and 36 add-ons. Sample mode, sample labels and manual sample import controls have been removed. The catalogue imports into the local D1 database automatically on the first package request. Missing entries are added once. Existing saved details are preserved. Previously imported sample records are upgraded to the supplied catalogue; custom unapproved drafts are preserved. Later deletions remain deleted rather than being recreated on every load.

The supplied entries are treated as approved catalogue data based on the owner's tables, not independently verified provider information. Admins can edit, deactivate or remove them. No package codes appear in the interface; internal IDs support updates and deletion.

Choose Data+Voice, Data Only or Add-ons in Connection type. Add-ons are matched only when Add-ons is selected. Cards show tax-inclusive prices, extra app benefits, night data, connection fees, renewal and validity where supplied. One-time add-ons show prices per activation; unspecified auto-renewal periods are not assumed to be monthly.

## Matching

Matching checks active status, approval, validity dates, connection type and eligibility before comparing data, calls, SMS and budgets. Upahara 499 and 727 require the government employee checkbox; their connection fees are Rs. 750 and Rs. 1,000 with no deposit. Hello AI 799 requires no student checkbox. App-specific and night data do not increase general Anytime data allowances.

Full matches are ordered by rental, deposit and data allowance, up to three results. If no full match exists, one nearest eligible option is shown. Ranking uses proportional allowance shortfalls and excess rental/deposit costs, plus penalties for missing requested unlimited benefits. It never bypasses eligibility or connection type. Detailed shortfall messages are hidden. If no eligible active tariff exists, no recommendation can be made. Budget matching uses excluding-tax prices. Connection fees are displayed separately.

## Hosting

For hosting, configure STAFF_USERNAME, STAFF_PASSWORD_HASH and STAFF_SESSION_SECRET as server-side Worker secrets using the values generated by the setup script. Local .dev.vars is not deployed automatically. Use HTTPS for secure admin cookies. Customers need no SMS service. Local database records under .wrangler/state remain separate from hosted records.

## Nearby data allowances

For numeric Anytime data requirements, recommendations include the closest eligible lower-data package alongside nearby full matches at or above the requested allowance. The nearest fully matching upper allowance is shown first, followed by the lower-data alternative and another suitable option when available, up to three cards. Lower-data cards are explicitly labelled and never claim to cover all entered needs. If no full match exists, nearest lower and upper options may both be shown. Eligibility, approval, active dates and selected connection category still apply. Requested unlimited data does not add limited-data alternatives when an unlimited match exists.
